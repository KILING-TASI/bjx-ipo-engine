# 独立引擎与主工作台的版本契约 v1.0

本批只改bjx-ipo-engine，未迁移或删除research-workbench代码。先保留旧入口，提供明确计算边界与同输入对照；主包是否接入由其负责任务另行实施。

## 独立接口

推荐用隔离子进程，避免两包同名Python模块污染。调用`python api.py`，stdin为UTF-8 JSON，stdout仅一个UTF-8 JSON响应；失败退出2，成功或资金不可行的有效计算退出0。不联网，不读取账户，不写文件。

请求只含api_version、operation、input：

```json
{"api_version":"1.0","operation":"scenario.v1","input":{"...":"沿用完整engine.py输入"}}
```

operation当前支持scenario.v1和cash_ledger.v1；input分别沿用engine.py、research.ledger既有契约，不转换单位、费用、日期、股数或未知。上面是结构说明，省略字段的JSON不能实际计算。Python调用可用api.calculate(request)，但应隔离导入环境。

响应包含api_version、engine_version、operation、input_sha256、status、result、error；错误响应的operation可能缺省。result与直接调用旧实现完全相等，含浮点与*_exact精确字符串的原有区别，不静默重新舍入。

| 状态 | 含义 |
|---|---|
| completed_with_limits | 已完成声明计算，来源与余股等局限保留 |
| infeasible | 现金计划撞资，停止回放；不是输入格式错误，也不假定融资 |
| failed | 版本、输入或计算不成立；result为null，不补零 |

无法序列化的非有限输入/结果、重复JSON字段与未知版本拒绝。方法和输入版本随响应保存，但本地哈希不证明数据真实或防联合改写。

也可用bjx.py api INPUT.json --out-dir NEW_DIR输出研究包。接口失败包标blocked，结果与失败原因仍保留；不覆盖旧目录。

## 同输入验收范围

对照独立旧入口与新v1接口：完整情景输出（整手、上限、零股成本、余股未知及敏感性、最低佣金、机会成本）和现金账输出（冻结、退款、获配本金、显式费用、精确金额、同日保守顺序与撞资）。Python返回值与隔离stdin返回值均核对，无主包修改或数据同步副作用。

这证明新接口没有改变独立引擎既有语义，**不证明主工作台与独立引擎已经等价**。双方尚未提供同一真实输入、期间、费用版本与完整输出的双实现对照。

## 尚不等价，不能删除主包功能

- 主包年度情景可能包含年度参与数、账户预算、资金复用或不同现金替代口径；独立接口仅单发行情景及明确事件账，没有annual.v1。
- 主包的公告核验、研究报告、资料归档与首次预测管理不由计算接口替代。
- 独立现金账使用明确事件日、到账顺序、已扣费回款和单列费用；不能将主包聚合参数直接塞入、默认为等价现金收益。
- 比例整手、未知余股、发行上限、获配本金持续留存和机会成本必须逐项对照；输入缺失不得由迁移层补默认或填零。

今后迁移须冻结同一输入/字段单位/规则与费用版本，双实现跑选定正向和失败案例，记录真实差异与未适用项。只有独立等价实现及验收齐全，才讨论停用主包某条旧计算入口；本批没有要求删功能，没有合并PR。

真实账户验收继续用户暂停；公开样本与教学对照不替代账户、全年或预测模型验证。
